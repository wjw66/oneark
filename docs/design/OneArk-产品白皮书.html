01

摘要与核心价值

每个人每天在会议、笔记、学习、创作与生活中产生大量材料，却散落在企业系统、聊天工具与临时文件里。它们帮组织完成当下工作，却难以沉淀为个人可迁移、可复用、可持续增长的资产。OneArk 把「原始证据、人工确认、资产可迁移」置于中心，而非把 AI 对话置于中心。

ABSTRACTv0.2 讨论稿
ONE-LINER · 一句话定位

每一次记录，都不应只变成一条转瞬即逝的笔记，而应沉淀为一组可验证、可关联、可迁移的个人资产。

以会议、笔记与日常材料为入口，在本地项目空间中保存原始材料，通过转写、结构化、检索与生成，把一次性内容转化为可持续积累的个人资产。

02

我们要解决什么问题

问题不是「如何再做一个聊天界面」，而是：如何让个人内容在不牺牲隐私与可迁移性的前提下，被可靠地保存、理解、检索与再次生产。

PROBLEM
TEMPORAL · 01

信息的短暂性

会议、讨论、灵感与学习结束后，往往只留零散记忆与不稳定的记录。素材缺检索、缺关系——任务、决策、知识之间从未被连起来。

MISMATCH · 02

个人资产与平台错位

企业系统与云端工具服务当下流程，未必服务个人长期发展。换团队、离职或迁工具后，参与形成的经验与脉络可能无法继续使用。

TRUST · 03

生成式 AI 的信任问题

用户常无法控制：原始材料存哪、什么被发往模型、结果能否溯源、能否批量导出、供应商停服后资产是否仍可用。

用户的真实痛点

隐私

05

设计目标与非目标

先把边界划清楚：什么必须做到，什么第一阶段绝不做。克制本身就是产品力。

GOALS
DESIGN GOALS · 要做到

设计目标

资产归用户控制 证据可追溯 默认本地处理 人工确认可介入 渐进式智能化 跨平台可用

项目数据可复制、备份、迁移与导出；派生内容能回到原始材料；不依赖云端也能捕获、保存与基础转写；用户可修订、确认任务、控制长期记忆写入；先保存检索、再引入 Agent；以 macOS 与 Windows 为第一批桌面目标。

NON-GOALS · 不做

非目标（第一阶段）

通用 Agent 平台 知识图谱替代全文检索 所有调用过 Agent 通用插件市场 默认上云 覆盖所有来源

在没有真实使用频率前，不引入通用插件、Agent 强制层、知识图谱或全平台覆盖——避免过早平台化带来的权限、数据与生命周期复杂度。

06

核心概念模型

项目空间是用户可见、可复制的资产边界：结构化数据库 + 可读文件。会议、笔记与导入的材料都进入同一套 capture 结构；SQLite 存实体、关系、索引与任务状态，原始文件落在文件系统，附件用相对路径，保证项目可整体移动。

CONCEPT
Project Space · 项目空间结构
项目空间/ ├── project.json ├── workspace.sqlite ├── capture/ │ └── item-id/ │ ├── metadata.json │ ├── source.wav / source.md │ ├── transcript.raw.json │ └── transcript.edited.json ├── knowledge/ ├── tasks/ └── exports/
DATA MODEL

原始资产 vs 派生资产

原始资产：录音/原件、原始转写、模型版本、时间戳、导入文件。派生资产：修订文本、摘要、任务、标签、知识条目、对外产物。派生不可覆盖原始，并保存来源引用、模型配置与生成时间。

CONFIDENCE

事实 · 推断 · 建议

区分材料直接提供的事实、提取的结构化信息、模型的推断与建议、用户确认后的长期资产。只有确认后的内容，才进入高置信度的长期知识或任务视图。

07

产品机制

四大机制支撑资产沉淀闭环：捕获沉淀、知识沉淀、工作产物、Agent 编排。确定性能力由应用服务直接提供，Agent 只处理需规划与确认的任务。

MECHANISM
M1 · 捕获与沉淀

先捕获 · 后转写

选择/创建项目 → 录音或导入 → 保存原始材料 → 后台转写/解析任务 → 本地模型处理 → 展示结果与时间戳 → 用户修订与确认。一期以会议为旗舰入口，不做实时转写，先验证资产闭环。

M2 · 知识沉淀

建议 + 确认

会议、Markdown、文档与笔记进入知识空间，先给来源、标签、关联与全文检索。AI 可建议归类，但绝不在用户不知情时永久写入。

M3 · 工作产物

模板 · 字段 · 溯源

产物优先从已确认资产生成。日报、周报、纪要、PPT、HTML、信息图、流程图是不同渲染目标，不混成一个不透明的 Agent 输出。

M4 · Agent

跨模块编排层

Agent 不是底层数据与模型服务的替代品。它处理需规划、检索、多步工具调用与确认的任务，如据一周材料生成周报草稿并列出每条结论来源。

08

信任与隐私模型

Local-first 不等于永远不联网：本地存储是默认路径、原始材料不要求先上传、本地转写可独立完成、远端模型由用户主动配置、外发内容与 endpoint 可见。

TRUST & PRIVACY
LOCAL-FIRST

默认本地

本地存储为默认路径；原始材料不要求先上传；本地转写可独立完成；远端模型必须由用户主动配置。

CLOUD BOUNDARY

云端边界透明

明确提示发送的是原始转写还是修订文本、是否含音频、用哪个 provider、重试是否会再发、结果如何写回本地。API key 不作普通项目文件复制。

PORTABILITY

可迁移性

不依赖在线服务即可取得原始材料、转写、元数据、知识条目、任务、产物及来源版本——方舟隐喻的落脚点：一舟承载，整船带走。

09

技术架构

一期采用模块化单体，仅为稳定变化点定义接口：CaptureSource / TranscriptionProvider / ProjectStore / GenerationService / Exporter。底层高性能用 Go，上层可扩展用 Python 或 TypeScript，数据库用 SQLite。

ARCHITECTURE
表现层 · React / Vite
编辑器、设置、列表与状态呈现。不使用 Next.js 的 SSR——一期是本地桌面应用。
桥接 · Wails
连接 Go 后端与前端 WebView，承载桌面窗口与系统能力调用。
应用服务层 · Go
项目空间、文件系统、SQLite、任务调度，以及 Python worker 的生命周期管理。
推理层 · Python Worker
加载 faster-whisper 执行 ASR 转写，向 Go 输出进度、错误与结果；未来可扩展长驻 streaming worker 支持实时转写。
可选 · 远端 LLM
摘要、抽取、生成可经 BYOK 接入各大 LLM API；外发内容、provider 与 endpoint 对用户透明可见。插件 / MCP / A2A 待权限与审计模型明确后再开放。

11

如何衡量成功

不以「支持多少模型或协议」衡量，而以沉淀闭环是否可信衡量。

METRICS
01
用户能在短时间内完成一次捕获并找到对应转写。
02
长音频与异常中断不会导致资产丢失。
03
原始内容、修订内容与生成内容可以区分。
04
用户可以按关键词、来源与项目回溯内容。
05
项目目录可以备份、移动与导出。
06
用户清楚知道哪些内容被发送到远端模型。
07
生成产物能够回到具体来源，而不是只能相信模型。
12

主要风险

提前识别并设防，避免在错误的方向上过度投入。

RISKS
中

跨平台捕获差异

macOS 与 Windows 权限、系统音频与设备行为不同，先固定一期支持的来源与录音范围。

中

模型质量与成本

本地模型带来体积、CPU/GPU、首启与版本管理问题；按需下载并记录版本，结果溯源到模型配置。

高

过早平台化

通用插件、Agent、MCP、A2A 与知识图谱会扩大复杂度，应在 P1/P2 形成真实使用频率后再引入。

高

许可证与模型权利

发布前逐项审核桌面框架、FFmpeg、模型权重、推理库与前端依赖的许可及再分发条件。

13

结论与承诺

长期价值不在于堆砌最多 AI 功能，而在于建立可信的个人资产底座：原始材料被保存，派生结果可追溯，用户拥有确认权，项目可以迁移。

CONCLUSION
THE PROMISE · 可验证的承诺

把每一次记录，可靠地沉淀为属于你自己的个人资产。

当这个承诺被真实用户反复验证，个人资产库、工作台、Agent、MCP / A2A 与内容生产能力才有稳定的数据基础与产品理由——而这一切，都装载在属于你自己的方舟里。
