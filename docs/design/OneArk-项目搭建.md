# OneArk 项目搭建（个人资产沉淀系统）

## 定位

OneArk = 本地优先的**个人资产沉淀系统**。以会议/笔记为高频入口，把工作、学习、创作、生活中转瞬即逝的内容，沉淀为可验证、可关联、可迁移、完全归属你的个人资产。

命名逻辑：**方舟** = 一舟承载完整的你、可整船迁移、不随平台/离职断层；会议只是「上船的第一批货」，工作只是其中一舱。

## 设计思想和大纲

1. local-first 原则至上，以「完整的个人」视角展开（工作只是其中一面），抓住知识工作者的痛点
2. 抓住最高频的会议场景，从音频/材料开始（旗舰入口）
3. 基于材料沉淀，打造个人资产库（跨工作/学习/创作/生活）
4. 基于资产库，打造个人工作台
5. 聚焦个人场景：画像 + 记忆 + 内容识别、生成汇报（日报、周报）、PPT、HTML、信息图、流程图等

## 用户痛点

1. 本地隐私至上，所有数据本地存储、不上云，材料长期沉淀为个人资产
2. 经历与成长沉淀
3. 可迁移的工作经历、经验与成长过程
4. 资产是个人的，不属于任何平台/公司，离职或换工具不断层
5. 生产高质量产物本身是个痛点

## 一阶段：捕获与转写

1. 收音 + 降噪（会议/笔记）
2. 音频转文字
3. ASR 纠错优化

## 二阶段：个人资产库（支持 DIY）

1. 基于上面的功能打造资产库体系
2. 待办事项
3. 个人收藏
4. 本周主线
5. 收藏文章提醒
6. Agent 自动记录对个人沉淀有用的内容
7. 知识库腐败检测：重复文件、文件内容重复整合、过时知识检测整合

## 三阶段：个人 Agent

1. 支持会话 Agent 模式
2. 画像 + 记忆
3. 内容识别、生成汇报（日报、周报）、PPT、HTML、信息图、流程图
4. MCP / A2A 模式
5. 自定义工作流

## 四阶段：增强功能（PRO 版）

1. 热点追踪（支持个人配置追踪的站点和规则）
2. 转写功能增强
3. 更复杂优秀的记忆、图谱能力
4. 卖云端存储收费
5. 卖定制款的耳机、录音卡片等

## 项目架构

1. 底层需要高性能支持的优先使用 Go 语言
2. 上层需要可扩展支持的优先使用 Python 或 TypeScript 语言
3. 数据库使用 SQLite
4. 架构原则：所有功能模块插件化，具体最佳实践参考 deepseek-harness 的架构设计（仅借鉴，不强制依赖）
5. 所有和 LLM 模型有关的交互都通过内置 Agent（pi-Agent），Agent 负责调用 LLM 模型、处理用户输入、生成输出
6. 稳定接口：`CaptureSource` / `TranscriptionProvider` / `ProjectStore` / `GenerationService` / `Exporter`

```text
│       ├── source.wav / source.md
│       ├── transcript.raw.json
│       └── transcript.edited.json

├── tasks/
└── exports/
```
